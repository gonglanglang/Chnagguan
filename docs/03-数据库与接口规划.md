# 「过关啦」数据库与接口规划文档

> **文档版本**：v2.0（加入修仙境界与进阶考核契约）  
> **说明**：本文档作为前后端联调、建表与代码生成的契约基准，真实建表详见 `backend/src/main/resources/db/schema.sql` 与 `SchemaUpgradeRunner`。

> [!NOTE]
> **v2.0 数据库与接口增量**：
> - 新增 `edu_realm` 表（`realm_code`、`realm_name`、`realm_order`、`grade_code`、`difficulty_label`、`unlock_gates`、`exam_question_count`、`exam_pass_score`）。
> - `app_user` 新增 `realm_code` 字段；`user_quiz_record` 新增 `realm_code` 与 `score` 字段（`mode` 新增 `ADVANCE_EXAM`）。
> - 学生端新增接口：`GET /api/app/realms`、`GET /api/app/realms/{realmCode}/chapters`、`POST /api/app/realm/exam/start`、`POST /api/app/realm/exam/submit`；`POST /api/app/quiz/start` 校验高境界拦截并回传 `suppressedMode`。
> - 管理端新增接口：`GET /api/admin/realms`、`PUT /api/admin/realms/{id}`、`PUT /api/admin/users/{id}/realm`。

## 一、核心 MySQL 数据库设计

所有表使用 `InnoDB` + `utf8mb4_unicode_ci`（确保 Emoji 如 `🌱🐉` 与数学符号 `∈∪∩√²³−` 正常存储）。

### 1.1 表清单总览

| 分类 | 表名 | 用途说明 |
|---|---|---|
| 用户与权限 | `app_user` | 前台学生用户基础信息与累计战绩汇总 |
| 用户与权限 | `sys_admin` | 管理后台管理员 / 教研账号 |
| 用户与权限 | `sys_oper_log` | 后台高危操作与内容变更审计日志 |
| 教研与题库 | `edu_grade` | 年级表（初一 `g7` ~ 高三 `h3`） |
| 教研与题库 | `edu_chapter` | 章节表（起步 51 章，支持后台新增自定义章节） |
| 教研与题库 | `edu_gate` | 关卡配置表（每章 4 关：基础/中档/拓展/压轴） |
| 教研与题库 | `edu_question` | 题目主表（支持静态单选题与动态参数模板题） |
| 教研与题库 | `edu_level_rule` | 创意段位规则表（起步 10 个段位） |
| 闯关与错题 | `user_gate_progress` | 用户关卡通关状态表（决定下一关解锁与星星数） |
| 闯关与错题 | `user_quiz_record` | 每次闯关/重做答题记录表（含题目快照与得分） |
| 闯关与错题 | `user_wrong_question` | 用户错题本表（记录错题、次数、已掌握状态） |
| 系统配置 | `sys_config` | 全局开关与运营参数（如游客试玩开关、公告） |

## 二、混合出题引擎设计（兼容原版 136 个动态关）

原版题库中 68 关为静态题（`qs`）、136 关为函数动态题（`gen`）。在 Java 后端通过 `QuestionEngineService` 统一封装两种出题方式：

1. **静态题 (`STATIC`)**：直接从 `edu_question` 中筛选启用题目（随机抽取 `gate.question_count` 道或按排序取题），如需要可对选项做服务端洗牌并重算 `answerIndex`。
2. **动态模板题 (`DYNAMIC_TEMPLATE`)**：
   - **路径 A（原版 136 关平滑迁移）**：每道原版生成器函数在 Java 中实现为带编码的受控生成器（如 `G7_C1_G1_1`、`G7_C3_G2_2` 等），内置 `R(min, max)`、`frac(n, d)`、`mkg(q, ans, wrongs)` 公共工具方法，保证与原版完全一致的数学精度和中文题干；
   - **路径 B（后台可视化新增参数化动态题）**：教研在后台可配置受控 JSON 规则，例如：
     ```json
     {
       "vars": { "a": [2, 9], "b": [1, 8] },
       "stemTpl": "若 |x - {{a}}| + |y + {{b}}| = 0，则 x + y =",
       "ansExpr": "a - b",
       "wrongExprs": ["a + b", "-a + b", "-a - b"]
     }
     ```
     后端使用受限算术求值器（仅允许加减乘除与变量名，禁止方法调用与脚本执行）生成具体题干、答案与 3 个不重复干扰项并洗牌。
3. **交卷一致性保证**：无论静态还是动态生成，一旦在 `POST /api/app/quiz/start` 生成题目，即把具体题干、洗牌后选项、真实答案索引写入 `user_quiz_record.question_snapshot_json` 与 Redis 会话，返回给客户端的仅含 `{ itemIndex, stem, options }`，彻底杜绝前端抓包看答案。

## 三、接口路由总览（RESTful API 规划）

统一响应格式：`{ "code": 200, "message": "ok", "data": ..., "timestamp": ... }`

### 3.1 学生端接口 (`/api/app/**`)

| 模块 | 方法与路径 | 说明 |
|---|---|---|
| 认证 | `POST /api/app/auth/login` | 账号密码登录（支持游客记录合并参数） |
| 认证 | `POST /api/app/auth/register` | 学生注册 |
| 认证 | `POST /api/app/auth/wx-login` | 微信小程序 `code` 一键登录 |
| 认证 | `POST /api/app/auth/logout` | 退出登录 |
| 个人中心 | `GET /api/app/user/profile` | 获取当前用户信息、累计过关数、当前段位与下一段位进度 |
| 个人中心 | `PUT /api/app/user/profile` | 修改昵称、头像、当前在读年级 |
| 章节闯关 | `GET /api/app/grades` | 获取启用年级列表及基础统计 |
| 章节闯关 | `GET /api/app/grades/{gradeCode}/chapters` | 获取某年级下所有启用章节及当前用户各章星数进度 |
| 章节闯关 | `GET /api/app/chapters/{chapterId}/gates` | 获取某章 4 关闯关地图（含解锁状态、是否过关、题数） |
| 闯关答题 | `POST /api/app/quiz/start` | 校验解锁状态后开启关卡，生成并返回题目（**不含答案**） |
| 闯关答题 | `POST /api/app/quiz/check-item` | （可选单题即时判题）提交单题答案，立即返回对错、正确答案与解析 |
| 闯关答题 | `POST /api/app/quiz/submit` | 整关交卷结算，更新过关进度、触发段位晋升判断、错题自动入库 |
| 错题本 | `GET /api/app/wrong-questions` | 分页获取待攻克错题（支持按 `gradeCode` / `chapterId` 筛选） |
| 错题本 | `POST /api/app/wrong-questions/redo/start` | 抽取最多 5 题生成错题重做会话 |
| 错题本 | `POST /api/app/wrong-questions/redo/submit` | 错题重做交卷：**答对自动标记已掌握，答错累计错题次数** |
| 错题本 | `PUT /api/app/wrong-questions/{id}/master` | 手动标记单题「已掌握，移出」 |
| 错题本 | `DELETE /api/app/wrong-questions/clear` | 清空当前用户未掌握错题 |
| 段位战绩 | `GET /api/app/levels` | 获取全部 10 个段位与用户达成状态 |
| 段位战绩 | `GET /api/app/user/chapter-records` | 获取「我的过关」各章战绩明细 |
| 版本更新 | `GET /api/app/version/latest` | 检测 App 最新版本（支持关联 GitHub Releases 与服务端配置兜底） |
