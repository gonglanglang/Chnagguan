# 「过关啦」迭代任务台账、开发规划与发版规范

> **必读要求**：每次新开 AI 会话承接研发需求时，必须先读取本文件与 [AGENTS.md](../AGENTS.md)、[02-开发规范.md](./02-开发规范.md)，按规范生成唯一任务编号登记后，再创建同名 Git 分支开展开发。

---

## 一、任务编号与开发流水线标准流程

1. **生成任务编号**：格式固定为 **`TASK-YYYYMMDD-NNN`**（如 `TASK-20261122-001`、`TASK-20261122-002`），按当日在下方任务台账递增编号。
2. **登记任务规划**：在动手编码前，在本文件「二、迭代任务台账」新增一行任务规划，并在「三、任务详细规划」补充改造模块、技术方案与本地验收清单。
3. **拉取分支开发**：基于最新 `main` 创建与任务编号同名的独立分支：
   ```bash
   git checkout main && git pull origin main
   git checkout -b TASK-YYYYMMDD-NNN
   ```
4. **本地测试与启动服务**：
   - 先跑通后端单测/构建（`cd backend && .\mvnw.cmd test`）与前端类型检查/构建（`pnpm typecheck` / `pnpm type-check`）；
   - 使用 [scripts/dev-local.ps1](../scripts/dev-local.ps1) 在本地启动后端 (`8080`)、管理后台 (`8848`)、学生端 H5 (`5174`) 进行联调测试。
5. **推送分支待合并**：自测通过后提交并推送任务分支到远程：
   ```bash
   git push -u origin TASK-YYYYMMDD-NNN
   ```
6. **合并与 Jenkins 部署**：用户在远程仓库审阅合并 `TASK-YYYYMMDD-NNN -> main` 后，进入 Jenkins 构建发布线上环境。

## 三、任务详细规划

### `TASK-20261122-001`：开发规范固化、Jenkins CI/CD 流水线部署与本地启动机制

- **需求目标**：
  1. 在每次新开会话必读的规范文件中，固化「生成任务编号 → 写规划 → 创建同名分支 → 本地测试并本地启动项目 → 推送远程分支 → 用户合并后 Jenkins 部署」全流程。
  2. 在生产服务器部署轻量化 Jenkins 流水线（适配 `2C / 1.7GiB RAM + 2GiB Swap` 资源约束），支持按参数构建并发布后端 Java 服务、管理后台 Web 与 App 下载官网。
  3. 提供本地 Windows 一键启动与状态检查脚本，实现新任务完成后直接帮用户本地拉起前后端测试环境。
- **技术要点**：
  - **Jenkins 部署架构**：安装 Jenkins LTS（`/opt/jenkins/`，绑定 `127.0.0.1:8088`、`--prefix=/jenkins`），通过 Nginx 反向代理暴露 `http://47.107.94.90/jenkins/`；配置清华源更新中心与 Pipeline 核心插件；限定内存 `-Xms192m -Xmx384m`。
  - **仓库流水线定义 (`Jenkinsfile`)**：经由 GitHub `codeload.github.com` 极速归档通道按指定分支秒级拉取最新源码后加载仓库根目录 `Jenkinsfile`；按顺序阶段（避免并发构建爆内存）执行，支持独立开关 `DEPLOY_BACKEND`、`DEPLOY_ADMIN`、`DEPLOY_DOWNLOAD`、`BRANCH_NAME`、`SKIP_TESTS`，复用 `/opt/jenkins/m2` 与 `/opt/jenkins/pnpm-store` 缓存，通过 `/usr/local/bin/guoguanla-deploy` 原子替换并校验健康检查。
  - **本地运行脚本 (`scripts/dev-local.ps1`)**：自动定位 JDK 21、检查 `backend/application-local.yml` 与 MySQL80，后台拉起 Backend(`8080`) / Admin(`8848`) / UniApp H5(`5174`)，PID 与日志写入 `$env:TEMP\guoguanla-dev\` 保持工作区干净。
