## 三、后端 Java 开发规范

### 3.1 分层与职责边界
- **Controller**：仅负责路由映射、入参 `@Validated` 校验、调用 Service、包装 `Result.ok(...)` 返回。**严禁**在 Controller 写 SQL/Wrapper 或复杂业务判断。
- **Service**：承载核心业务逻辑与事务控制（`@Transactional(rollbackFor = Exception.class)`）。写操作超过 1 张表必须显式加事务。
- **Mapper**：仅负责数据持久化。简单单表 CRUD 使用 `LambdaQueryWrapper` / `LambdaUpdateWrapper`（禁止在代码中硬编码数据库字段字符串，必须使用 `Entity::getField` Lambda 引用）。
- **对象分层**：
  - `Entity`：与数据库表一一对应，**严禁直接作为 Controller 出参或入参**；
  - `DTO` / `Req`：接口入参对象，必须附带 JSR-303 校验注解（`@NotBlank`、`@NotNull`、`@Min`、`@Max`）；
  - `VO` / `Resp`：接口出参对象，明确脱敏（如手机号、OpenID、管理员密码哈希严禁外泄）。

### 3.2 统一返回体与错误码约定

所有 HTTP 接口均返回统一 JSON 结构 `Result<T>`：

```json
{
  "code": 200,
  "message": "ok",
  "data": {},
  "timestamp": 1763600000000
}
```

错误码分段约定（定义在 `ErrorCode` 枚举中，全局唯一）：
- `200`：成功
- `400`：参数校验失败 / 非法请求
- `401`：未登录或登录已过期（需区分学生端与管理端）
- `403`：无权限操作（账号禁用或角色不足）
- `404`：目标资源不存在
- `500`：系统未知异常（向前端屏蔽堆栈细节，服务端打印完整日志）
- `10001 ~ 10999`：用户/认证模块业务错误（如账号禁用、微信登录失败）
- `20001 ~ 20999`：题库/关卡业务错误（如关卡未解锁、关卡暂无题目、模板解析失败）
- `30001 ~ 30999`：答题/错题模块业务错误（如答题会话已过期、重复提交）

### 3.3 核心安全与防作弊规范
1. **双端鉴权隔离**：
   - 学生端接口前缀统一 `/api/app/**`，使用用户 Token 校验；
   - 管理后台接口前缀统一 `/api/admin/**`，使用管理员独立 Token 体系（`StpAdminUtil`）及 `@SaCheckPermission` 权限校验；学生端 Token 绝不能访问 `/api/admin/**`。
2. **严禁答题前泄题**：
   - 开始闯关接口返回 `QuizQuestionVO` 时，**禁止包含 `answer`、`answerIndex`、`analysis` 字段**；
   - 题干与选项生成完毕后在服务端写入答题会话快照（Redis / `user_quiz_session`），用户提交答案时由服务端比对判分。
3. **动态出题引擎安全边界**：
   - 严禁对后台输入的任意字符串执行无沙箱 `ScriptEngine`（防止 RCE 代码注入）；
   - 动态模板仅允许通过**白名单参数规则 + 受控数学表达式求值器 / 预注册 Java Generator Bean** 执行。
4. **敏感信息与审计**：
   - 管理员密码采用 BCrypt 加密存储；
   - 后台对用户的禁用/启用、题目删除、清空/导入题库、修改段位配置等高危操作，必须通过 AOP 切面记录 `sys_oper_log`。

### 3.4 性能与分页规范
- 任何可能返回多条数据的查询接口（用户列表、题目列表、错题列表、答题历史）**必须分页**，禁止无 `LIMIT` 全表加载。
- 51 章与关卡目录属于高读低写数据，可按 `grade_code` 缓存至 Redis，并在后台变更章节/关卡/题目上架状态时主动失效缓存。

## 四、学生端 UniApp 开发规范 (`frontend-uniapp/`)

### 4.1 目录结构约定

```text

├── api/                # 按模块拆分的接口调用（auth.ts / quiz.ts / wrong.ts / user.ts）
├── components/         # 公共业务组件（RankCard.vue / GateItem.vue / MathText.vue）
├── pages/              # TabBar 主页面
│   ├── home/           # 章节闯关（年级/章节/关卡地图）
│   ├── wrong/          # 错题本
│   └── mine/           # 我的过关与个人中心
├── subpackages/        # 分包页面（控制主包体积 < 2MB，适应微信小程序限制）
│   ├── quiz/           # 闯关答题、错题重做、结算页
│   └── user/           # 登录页、资料编辑、各章战绩明细
├── stores/             # Pinia 状态管理（user.ts / quiz.ts / app.ts）
├── styles/             # theme.scss（绿色主题变量）与全局样式
├── types/              # TypeScript 类型定义（与后端 VO 对齐）
└── utils/              # request.ts（统一请求拦截器）、storage.ts、format.ts
```

### 4.2 编码与跨端兼容规范
1. **组件语法**：统一使用 `<script setup lang="ts">`，严禁混用 Options API。
2. **禁止原生 DOM/BOM**：严禁出现 `document.`、`window.`、`localStorage.`，本地存储统一封装在 `utils/storage.ts` 中调用 `uni.getStorageSync` / `uni.setStorageSync`。
3. **尺寸与主题**：样式单位优先使用 `rpx`（750rpx 设计基准）；主题色使用 CSS 变量（`--color-primary: #0284c7`、`--color-bg: #f6f7f9` 等，并兼容自定义主题切换），方便后续切换或跟随 UI 库主题。
4. **网络请求封装 (`utils/request.ts`)**：
   - 自动注入请求头 `Authorization: Bearer <token>`；
   - 统一拦截 `code !== 200` 并给出 `uni.showToast` 提示；
   - 拦截 `401` 自动清理过期登录态并引导跳转登录页（带防重入锁）。
5. **数学文本渲染**：所有题干与选项通过统一组件 `<MathText :content="..." />` 渲染，前期渲染 Unicode 数学字符，后续升级 LaTeX 时只需改一处组件。
6. **分包体积控制**：微信小程序主包上限 2MB，答题页、登录设置页等非 TabBar 页面优先放入 `subpackages/`，静态大图放 CDN 或对象存储。

### 4.3 骨架屏（Skeleton）接入与同步维护规范（强制）
1. **全页面适配接入要求**：
   - `frontend-uniapp/` 下的**全部页面**（包含 `src/pages/` 全部 TabBar 页与 `src/subPages/` 全部分包页面）均须适配并接入与当前页面视觉结构一致的骨架屏；
   - 统一基于 `@wot-ui/ui` 的 `<wd-skeleton animation="gradient" />` 实现，配合 `styles/theme.scss` 中的 `--wot-skeleton-col-bg`、`--wot-skeleton-animation-gradient` 变量兼容浅色/暗黑双主题；禁止在页面主体初始化加载态使用裸 `<wd-loading />` 转圈代替骨架屏（按钮局部提交加载态除外）。
2. **结构一致性与跨端单位约束**：
   - 骨架屏外层容器优先复用对应页面的真实卡片容器类（如 `.chapter-card`、`.gate-card`、`.series-card`、`.wrong-card`、`.essay-card`、`.question-card`、`.profile-card` 等），保证圆角、边框、阴影与间距 1:1 对齐；
   - `<wd-skeleton :row-col="..." />` 内联配置禁止使用 `rpx`（H5 端内联 `rpx` 无法被 PostCSS 转换会失效），统一使用 `%` 与 `px` 配合外层 `rpx` 容器布局，确保 H5 / App / 微信小程序全端一致生效。
3. **页面样式结构更新同步红线**：
   - **如果以后任何页面进行样式重构、布局排版调整、模块增删或卡片字段变更，必须同步更新该页面对应的骨架屏结构与占位参数**，严禁只改正式内容区域而遗漏骨架屏导致加载闪烁或错位；
   - 代码审查、提交自查与 AI 协作交付前均需核对本条目。
4. **防闪烁加载策略**：
   - 对于 TabBar 等高频切换页面（`首页`、`修炼`、`错题本`、`我的`），仅在首屏尚无数据（`loading && list.length === 0` 或首次初始化未完成）时展示骨架屏；后续 `onShow` 静默刷新已有数据时不得覆盖已有内容重复闪现骨架屏；切换筛选条件/境界 Tab 重新拉取数据时允许展示列表骨架屏。

### 4.4 全局缓存对象开发规范（强制，Flutter / UniApp 全客户端通用）

> ⚠️ **开发红线**：今后客户端任何需要本地持久化缓存的场景，**必须统一登记并挂载到全局缓存对象中管理**，严禁在页面或业务模块中私自散落读写底层存储 API。

1. **什么是「全局缓存对象」**：
   - **全局缓存对象**（Flutter 端为 [`frontend-flutter/lib/core/cache/global_cache.dart`](../frontend-flutter/lib/core/cache/global_cache.dart) 中的 `GlobalCache` 及其全局单例 `globalCache`；UniApp 端为 `frontend-uniapp/src/utils/storage.ts` 的统一存储对象）是整个客户端**唯一合法的本地持久化缓存总控对象与键值注册表**。
   - 它的核心含义是将分散在各业务模块中的本地状态（登录凭证、用户快照、主题偏好、接口环境、课堂上次观看小节、公告已展示版本等）收口到一个具备**统一键名清单（`GlobalCacheKey`）、统一类型转换、统一升级保活策略与统一清理边界**的对象中，彻底杜绝“魔法字符串键名冲突、升级覆盖误删登录态、清理缓存范围失控、难以排查缓存项”等问题。
2. **新增缓存字段的强制三步流程**：
   - **第一步（登记元数据）**：在全局缓存对象的 `GlobalCacheKey` 枚举 / `GlobalCache.registry` 注册表中新增枚举项，明确填写：
     - `storageKey`（统一以 `ggl_` 为前缀的英文小写下划线键名）；
     - `description`（清晰的简体中文用途说明）；
     - `category`（所属分类：`auth` 登录态 / `preference` 偏好设置 / `learning` 学习与观看进度 / `lifecycle` 版本与弹窗状态 / `temporary` 临时缓存）；
     - `preserveOnAppUpdate`（覆盖安装新版本 App 时是否保留，默认 `true`）；
     - `preserveOnCacheClear`（用户点击「清理缓存」时是否保留）。
   - **第二步（封装强类型读写方法）**：在 `GlobalCache` 对象上提供具名 getter / setter（内部做好 JSON 容错解析与默认值兜底），严禁对外暴露原始 `SharedPreferences` 实例。
   - **第三步（补齐单元测试）**：在 `frontend-flutter/test/` 中为新增缓存项补充读写、异常容错及清理边界单测。
3. **禁止行为（红线）**：
   - **严禁**在任何 Page、Widget、Provider、Service 中直接调用 `SharedPreferences.getInstance()`、`prefs.getString(...)`、`uni.getStorageSync(...)` 或 `localStorage` 读写未在全局缓存对象中登记的键名；
   - **严禁**在版本升级逻辑中清空 `category == auth`（如 `accessToken`、`userProfile`）与核心用户偏好缓存，确保用户安装新版 App 后无感保持 30 天登录态。
4. **当前已登记核心缓存清单（`GlobalCache`）**：
   - `accessToken` (`ggl_access_token`)：学生端 30 天登录 Token（升级与清缓存强保留）；
   - `userProfile` (`ggl_user_profile`)：当前登录学生档案快照（升级与清缓存强保留）；
   - `rememberedAccount` (`ggl_remembered_account`)：登录页记住的用户名；
   - `guestPassedIds` (`ggl_guest_passed_ids`)：游客模式本地通关关卡 ID 集合；
   - `isDarkMode` / `themeHex` / `themeName`：外观与主题色偏好；
   - `customApiBaseUrl`：自定义接口环境地址；
   - `lastWatchedVideoLessons` (`ggl_video_last_lessons`)：课堂各视频系列上次观看小节映射（`seriesId -> lessonId`）；
   - `lastAnnouncementVersion` (`ggl_last_announcement_version`)：已自动弹出过修炼公告的 App 版本标识（`<version>+<versionCode>`，升级新版本后自动再触发一次）；
   - `smartBoardDraft` (`ggl_smart_board_draft`)：首页智能手写画板最近草稿快照（含当前题干、笔迹、几何图形、AI 思路与解题过程板书，支持清理临时缓存时释放）；
   - `smartBoardPrefs` (`ggl_smart_board_prefs`)：画板个人偏好（默认纸张样式、笔触粗细、防误触与橡皮擦模式）。

## 六、数据库设计规范

1. **字符集**：所有表统一使用 `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci`（必须支持题目中的 Emoji 及各种数学 Unicode 符号如 `🌱`、`√`、`∈`、`∀`、`∃`、`²`、`³`）。
2. **命名规范**：表名、字段名全小写下划线 `snake_case`，表名按业务前缀归类（`sys_` 系统、 `app_` 用户、`edu_` 教研题库、`user_` 学习行为数据）。
3. **通用审计字段**：核心业务表标配：
   - `id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT`
   - `created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP`
   - `updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP`
   - `deleted TINYINT NOT NULL DEFAULT 0`（重要基础表使用逻辑删除）
4. **JSON 字段使用**：动态题模板参数、答题选项快照等结构化但无需高频索引的字段可使用 MySQL `JSON` 类型，但查询过滤列（如 `grade_code`、`chapter_id`、`gate_id`、`user_id`、`status`）必须独立建列并加索引。

## 七、Git 分支、本地启动与 Jenkins 发布规范

### 7.1 任务编号与分支强制规范（每次新会话必做）
1. **任务编号规则**：每次新开会话承接开发需求前，必须先生成唯一任务编号：**`TASK-YYYYMMDD-NNN`**（按当日顺序递增，如 `TASK-20261122-001`），并在 [05-迭代任务与发版规划.md](./05-迭代任务与发版规划.md) 中补充任务目标与方案记录。
2. **分支隔离开发**：必须基于最新 `main` 创建**与任务编号同名**的分支：
   ```bash
   git checkout main && git pull origin main
   git checkout -b TASK-YYYYMMDD-NNN
   ```
3. **禁止直接向 `main` 提交或跳过合并直接改线上**：开发并本地验证完毕后，仅推送任务分支至远程仓库：
   ```bash
   git push -u origin TASK-YYYYMMDD-NNN
   ```
   待用户在远程仓库完成 `TASK-YYYYMMDD-NNN -> main` 合并后，再通过 Jenkins 流水线发布生产环境。

### 7.2 Git Commit 规范（Conventional Commits）
格式：`<type>(<scope>): <简明中文或英文描述>`（建议在末尾或范围关联任务编号）
- `feat`: 新增功能（如 `feat(quiz): 新增闯关判题与升段计算接口`）
- `fix`: 修复 Bug（如 `fix(wrong): 修复错题重做答对未移出列表的问题`）
- `docs`: 文档更新（如 `docs: 更新数据库接口规划文档`）
- `refactor`: 重构代码（不改变对外行为）
- `style`: 格式调整 / UI 样式微调
- `chore`: 依赖升级、构建配置等

### 7.3 环境变量与敏感文件管理
- 仓库内提交 `.env.example` / `application-example.yml` 作为配置模板；
- `.env.local`、`application-local.yml`、`*.pem`、`node_modules/`、`dist/`、`target/` 必须列入 `.gitignore`。

### 7.4 本地调试启动与测试规范
- **测试以本地环境为主**：开发完成后，必须在本地运行全量或相关测试并通过类型检查，同时在本地拉起前后端服务便于用户联调验证：
  - 一键启动：`powershell -ExecutionPolicy Bypass -File scripts/dev-local.ps1 -Action start -Target all`
  - 停止 / 状态：`scripts/dev-local.ps1 -Action status` / `scripts/dev-local.ps1 -Action stop`
  - 本地默认访问入口：
    - 后端服务：`http://localhost:8080`（Knife4j：`http://localhost:8080/doc.html`）
    - 管理后台：`http://localhost:8848`
    - 学生端 H5：`http://localhost:5174`

### 7.5 Jenkins CI/CD 生产发布规范
- **流水线地址**：`http://47.107.94.90/jenkins/`（任务名：`guoguanla-deploy`，由根目录 `Jenkinsfile` 驱动）。
- **构建参数**：支持 `BRANCH_NAME`（合并后默认 `main`）、`DEPLOY_BACKEND`、`DEPLOY_ADMIN`、`DEPLOY_DOWNLOAD`、`SKIP_TESTS` 独立开关。
- **生产部署隔离**：Jenkins 仅拉取远端 Git 代码并在服务器构建后通过 `/usr/local/bin/guoguanla-deploy` 原子替换部署，绝不把生产配置 `/opt/guoguanla/application-prod.yml` 写入仓库。

### 7.6 AI 新会话协作与验证清单
每次在新的 AI 会话中完成一段开发任务前，**必须完成并核对**：
1. 是否已阅读 `AGENTS.md`、`docs/02-开发规范.md`、`docs/05-迭代任务与发版规划.md` 及对应模块文档？
2. 是否已生成唯一任务编号并写入 `docs/05-迭代任务与发版规划.md`，且已在同名分支 `TASK-YYYYMMDD-NNN` 上开发？
3. 接口与数据结构是否与 `docs/03-数据库与接口规划.md` 保持一致（如有变动已同步更新文档）？
4. 改动后是否已本地运行测试/类型检查、本地启动好服务，并仅推送任务分支 `TASK-YYYYMMDD-NNN` 至远程仓库？
